[H5-6] Unions of Attribute Definitions

An attribute definition A is a union of existing attribute definitions A1,...,An if it validates any attribute that is valid according to at least one of A1,...,An. There are two equivalent ways how to build a union of existing attribute definitions as a Handle-based FDO attribute definition.

[H5-6a] Unions implemented by JSON Schemas

The FDO record of the attribute definition A contains a JSON schema which encodes a union of attributes A1,...,An. In detail, the attribute 21.T11969/Data applies attribute referencing to point to the attribute 21.T11969/JsonSchema, which has as its value a JSON schema. The JSON schema uses the keyword anyof to compose the different attribute definitions A1,...,An into a union and potentially overwrite their cardinalities into a common cardinality.

The following FDO attribute definition record defines a union of a name and a full name.
PID of Attribute Definition Example Value
21.T11969/Type FDO_Attribute
21.T11969/Profile 21.T11969/AttributeDef
21.T11969/Name Full_Name_or_Name
21.T11969/Description Either a full name or a name.
21.T11969/Cardinality 0..1
21.T11969/Data 21.T11969/JsonSchema
21.T11969/JsonSchema 
{"$ref": "https://raw.githubusercontent.com/fairdo-org/handle_fdo_specification/refs/heads/main/json-schema/%5BH5-6%5D_Union/AttrDef_Union_Full_Name%2BName.json"}
FDO record of attribute definition (fictionary PID: 21.T11969/Full_Name_or_Name)
The full validation schema for the union attribute can be found here. The validation schema is constructed as follows:
  • line 3: identifier of the attribute definition
  • line 4: name of the attribute
  • line 5: description of the attribute
  • line 7: the plain syntax (as given in lines 41, 81, 122, 163) is wrapped into the handle record syntax
  • lines 23-24, 83-84, 104-105, 164-165: The union cardinality is set to 0-1. Hence, either exactly 0-1 name, or exactly 0-1 full name can appear in the handle record.
  • lines 41, 81, 122, 162: references to the syntax of `21.T11969/Name` and `21.T11969/Full_Name`

This schema validates any handle record that has either 0-1 value representing a full name, or 0-1 value representing a name, for example record 1 and record 2.

[H5-6b] Unions implemented on Handle-record level

The FDO record of the attribute definition A must specify the attributes 21.T11969/ValidationMechanism and 21.T11969/DataType to define a union of attributes A1,...,An. In detail, the following attributes must be in the attribute definition:
  • (21.T11969/ValidationMechanism, Union) to state that this attribute definition is a union
  • (21.T11969/DataType, A1), ..., (21.T11969/DataType, An) to state that the union contains the attribute definitions A1,...,An.
The following FDO attribute definition record defines a union of integers in the interval [1990,2000] and [2010,2020].
PID of Attribute Definition Example Value
21.T11969/Type FDO_Attribute
21.T11969/Profile 21.T11969/AttributeDef
21.T11969/Name year_1990s_2010s
21.T11969/Description Any year in the 1990s and 2010s.
21.T11969/Cardinality 1
21.T11969/Data Not_Applicable
21.T11969/ValidationMechanism Union
21.T11969/DataType 21.T11969/example_integer_1990s
21.T11969/DataType 21.T11969/example_integer_2010s
FDO record of attribute definition (fictionary PID: 21.example/union_attribute01)
The attribute definition validates for example the attributes 
(21.example/union_attribute01, 1993)
and 
(year_1990s_2010s, 2010).
