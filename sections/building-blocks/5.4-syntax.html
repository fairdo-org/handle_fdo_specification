[H5-4] Syntax

There are two ways how to encode syntactical validation rules in the Handle record:

[H5-4a] Syntax implemented by JSON Schemas:

The FDO record specifies a JSON schema which contains all validation rules through the attribute 21.T11969/Data. This attribute applies attribute referencing to point to the attribute 21.T11969/JsonSchema, which has as its value a JSON schema. The JSON Schema encodes the following five basic validation rules:
  1. An attribute states to follow one of the primitive data types “string”, “number”, “integer” and “boolean” using the `type` keyword.
  2. An attribute states to comply with a regular expression using the `pattern` keyword.
  3. An attribute states to lie within a numeric range using the keywords `minimum`, `exclusiveMinimum`, `maximum` or `exclusiveMaximum`.
  4. An attribute states to be equal to one element from a whitelist through the `enum` keyword.
  5. An attribute states to be not equal to all elements from a blacklist through combining `not` with `enum`.

The full validation schema for the URL attribute can be found here. The validation schema is constructed as follows:
  • line 3: identifier of the attribute definition
  • line 4: name of the attribute
  • line 5: description of the attribute
  • line 7: the plain syntax (as given in lines 41, 81) is wrapped into the handle record syntax
  • lines 22-24, 83-84: The URL is given a cardinality for validation in the Handle record. A URL can appear between 1-10 times in the handle record.
  • lines 41, 81: reference to the syntax of a URL

{
  "responseCode": 1,

Services such as the Data Type Registry implement the attribute and schema generation such that this complexity is hidden from the user.

[H5-4b] Syntax implemented on Handle-record level:

The FDO attribute definition is fully encoded on the Handle record level, simply relying on a reference to a syntax definition. To specify that [H5-4b] is used to encode the syntax of an attribute, the following two attributes must be used in the FDO record of the attribute definition:
  1. (21.T11969/ValidationMechanism, Syntax)
  2. (21.T11969/DataType, [reference to a syntax definition]).
Syntax Definitions are themselves FDOs and encode the five basic validation rules in their records. They follow the syntax definition profile with the PID 21.T11969/SyntaxDef and contain the attributes listed in Table 5.

An implementation of an FDO validator would be able to validate the attribute definition `21.T11969/URL` against the example Handle records record 1 and record 2.

Note that both ways can be combined by using all attributes 21.T11969/Data, 21.T11969/JsonSchema, 21.T11969/DataType, and 21.T11969/ValidationMechanism simultaneously. In this case, when creating or updating this FDO attribute definition, it must be checked that both ways induce the same syntax validation rules.
