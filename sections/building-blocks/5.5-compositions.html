[H5-5] Composition of Attribute Definitions

A composition `A` of attribute definitions A1, A2, ... is instantiated in a handle value as JSON object with properties. Each property corresponds to one attribute Ai. The key of the property is either the names or the PID of an attribute definition. Values of properties are either lists or simple values, depending on the cardinality of the attribute. In more details, if the attribute definition Ai has a cardinality larger than 1, then the property is an array with the respective cardinality. The cardinality of Ai can also be overwritten in the composition (only narrowing down the cardinality is possible, e.g. from 1..10 to 2..5), to accomodate to the new context.

There are two ways how to encode the composition of attribute definitions in Handle-based attribute definitions:

[H5-5a] Compositions implemented by JSON Schemas

  • The FDO record of the attribute definition A contains a JSON schema which encodes a composition of attributes A1,...,An. In detail, the attribute 21.T11969/Data applies attribute referencing to point to the attribute 21.T11969/JsonSchema, which has as its value a JSON schema.
  • The JSON schema implements a composition by combining the syntax of existing attributes A1,...,An, their name, descripion, and their cardinalities into a new schema. The cardinalities can be narrowed down, if required.
  • The resulting composition `A` is a new attribute definition that has its own name, description and cardinality. The cardinality of `A` gives information on how often `A` MUST be repeated in an FDO record.
The following FDO record contains the attribute definition of a full name, which is a composition of a first name and a last name.

21.T11969/Cardinality 0..2

Attribute FDO record (fictionary PID: 21.T11969/Full_Name)
The full validation schema for the `21.T11969/Full_Name` attribute can be found here. The validation schema is constructed as follows:
  • line 3: identifier of the attribute definition
  • line 4: name of the attribute
  • line 5: description of the attribute
  • line 7: the plain syntax (as given in lines 41, 81) is wrapped into the handle record syntax
  • lines 23-24, 83-84: The `21.T11969/Full_Name` is given a cardinality for validation in the Handle record. A `21.T11969/Full_Name` can appear between 0-2 times in the handle record.
  • lines 41, 81: reference to the subschema composing the first name and the last name.
    • lines 8-20: attribute definition of the first name, including
      • its name (line 9)
      • its description (line 10)
      • its identifier (line 11)
      • its syntax (lines 12-17)
      • its cardinality (lines 18-19). The cardinality is narrowed down from 0-5 (in the attribute definition of `21.T11969/First_Name`) to 0-3.
    • lines 21-31: attribute definition of the last name, including
      • its name (line 22)
      • its description (line 23)
      • its identifier (line 24)
      • its syntax (lines 25-28)
      • its cardinality (lines 29-30). The cardinality is narrowed down from 0-5 (in the attribute definition of `21.T11969/Last_Name) to 1-3.
    • Note that there is a subtle difference in creating attribute definitions: The two properties in this example subschema are called `First_Name` and `21.T11969/Last_Name`. Depending on how this attribute should be instantiated, one either has to use the human-readable label (`First_Name`) or the PID (`21.T11969/Last_Name`) as property. See also the two example records below.

This schema validates any handle record that has between 0-2 full names in its record, for example record 1 and record 2.

A composition of attributes is implemented by setting 2-3 attributes in the FDO record:
  1. (21.T11969/ValidationMechanism, InlineCombination)
  2. (21.T11969/DataType, [reference to attribute definition]), repeated multiple times.
  3. (21.T11969/CardinalityOverride, 
    {"Attribute PID 1": "new cardinality 1", "Attribute PID 2": "new cardinality 2", ... })
    to override the cardinalities of the inline combination
The following FDO record contains the attribute definition of a full name, which is a composition of a first name and a last name.
PID of Attribute Definition Example Value
21.T11969/Type FDO_Attribute
21.T11969/Profile 21.T11969/AttributeDef
21.T11969/Name Full_Name
21.T11969/Description Full name of a person. A person has between 0-2 full names.
21.T11969/Cardinality 0..2
21.T11969/Data 21.T11969/Not_Applicable
21.T11969/ValidationMechanism InlineCombination
21.T11969/DataType 21.T11969/First_Name
21.T11969/DataType 21.T11969/Last_Name
21.T11969/CardinalityOverride {"21.T11969/First_Name": "0..3", "21.T11969/Last_Name": "1..3"}
Attribute FDO record (fictionary PID: 21.T11969/Full_Name)

An implementation of an FDO validator would be able to validate the attribute definition `21.T11969/Full_Name` against the example Handle records record 1 and record 2.

Note that both [H5-5a] and [H5-5b] can be combined by using all attributes 21.T11969/Data, 21.T11969/JsonSchema, 21.T11969/DataType, 21.T11969/ValidationMechanism, and 21.T11969/CardinalityOverride simultaneously. In this case, when creating or updating this FDO attribute definition, it must be checked that both ways induce the same syntax validation rules.
